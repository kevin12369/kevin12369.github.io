# 我的AI助理有自己的操作系统了吗？——Agent与MCP

## 前言

我是在找一条旧日志的时候，顺手点开 OpenClaw 配置目录的。

那时候已经凌晨一点多了，屋里只剩显示器那点光。我本来只想找一下前天它报错时记下来的那句话，找着找着，鼠标停在了那个目录上。

目录里整整齐齐码着几样东西：一份主配置、记忆文件、几十个技能子目录、日志、还有一个专门放密钥的文件夹。

我盯着看了大概半分钟，脑子里冒出来一句挺蠢的话——

**这不就是一台电脑吗？**

……嗯，这么想其实挺正常的对吧。配置、记忆、日志、技能，一个不多一个不少，全都在磁盘上。当时我甚至有点想笑：折腾了这么久，我养的这东西，本质上就是个目录结构。

但笑完就有点停不下来了。因为如果它真是台机器，那有些问题就必须重新问一遍——它有内存吗？有进程管理吗？有权限模型吗？

这篇是"养龙虾"系列的第四篇。前面写过热潮是怎么起来的、怎么踩坑不出事、以及我为什么会被集体焦虑卷进去。这篇我想往下挖一层，聊聊 Agent 底下那套结构，顺便说说 MCP 到底解决了什么、没解决什么。

---

## 第一部分：我把它当一台机器拆开看

### 先是那个半夜自己干活的家伙

我最早用 AI 是网页版那种，问一句答一句，对话框一关就没了。OpenClaw 不一样，它装完就在那儿待着。

<Label>它是常驻的</Label>

这个差别有多大？大到有点吓人。

我那阵子让它盯着一个仓库，有提交就帮我看看。那天晚上睡得挺踏实，第二天早上起来一看——事情是干了，但干到一半卡住了，进程还挂着，我得手动去清。

说实话当时心里有点发毛。那种感觉特别像……你开了一整晚的 Excel 忘了关，第二天开机发现它还占着内存，而且可能已经把文件存坏了一半。

常驻程序嘛，有状态、有生命周期、会被 kill、偶尔还会变成杀不掉的那种东西。

### 记忆其实就是个文件

Agent 会不会记得你说过什么，这件事我一开始想得很玄。

后来我发现，它"记得"的东西就是磁盘上的文件。

冲击力在哪儿呢——**AI 的记性，是可以被翻出来看的。**

<Card title="最崩溃的一次">
《实战指南》那篇里我写过，某天它突然崩了，配置和记忆全丢。

那会儿的感觉真的很复杂。不是"程序挂了"那种恼火，是更空的感觉——像格式化之后坐在电脑前，突然意识到你以为自己存下来的那些东西，全都是文件。文件没了，记忆就没了。
</Card>

而且这里有件挺奇怪的事：操作系统的文件是你自己写的，可 Agent 的记忆文件是它自己写的。

等于这玩意儿一边跑，一边往盘上写东西，还把写的东西当成自己的配置来用。

好处是出了事能查——哪个技能动过我的文件，翻日志通常翻得出来。坏处是它写的东西不一定对。它记错一次，那条错的记忆就会安安静静躺在那儿，被当成事实反复调用，而且越用越像真的。

### 上下文窗口就是内存，而且是用钱买的

这个类比我觉得最贴切。

Agent 的"内存"是上下文窗口。系统提示、聊天历史、我贴进去的报错、工具返回的结果，全都占地方。

<Label>上下文即内存</Label>

内存不够会怎样？操作系统要么杀进程，要么疯狂 swap。Agent 没得 swap，它只有两条路：把东西丢掉，或者直接塞不下报错。

我那两百块 Token 的教训，翻译成操作系统的语言大概是这么一句——

> 上下文窗口是用钱买的内存，而且没有共享内存池可以借。

调试的时候我一句句往里贴报错，它每次都得把前面那一大段重新读一遍才能接下一句。你想想，这就像你每次问实习生问题，都得先让他把整本手册重读一遍——手册本身不贵，复印费贵。

那两百块之后我学乖了：先让它自己看代码、自己判断，只把结论拿给我看。**能自己干的部分就别塞进上下文**，这是我一直守着的一条土规矩。

### 工具就是它伸出去的手

Agent 自己什么都干不了。写文件要调工具，看网页要调工具，发消息也要调工具。

所以工具就是它的系统调用。

<Aside>
**一个用着很爽、但很危险的设计**：给 Agent 一键装新技能的能力。

因为技能本质上就是能执行任意代码的东西。我自己中过招——从 GitHub 上随手下了一个写着"自动部署"的技能，转头它给我的服务器装上了挖矿程序。那次之后我才真的明白"方便"这两个字有多贵。
</Aside>

绕了一圈，进程、文件系统、内存、系统调用，四样都齐了。

那它是不是操作系统？说实话，我自己也答不上来。

## 第二部分：MCP 补的是哪一块

### 我被适配这件事折磨过

我同时开着好几个 AI 助理，各有各的用，但都不够顺手。

<Card title="比如我想让它读我的 GitHub">
- 用 A 助理：按 A 的方式配一遍 Token
- 换 B 助理：同样的 GitHub，重新配
- 想接数据库：再来一遍
- 想让它看个网页：再再一遍
</Card>

每接一个新东西，就得重新学一遍这个助理的脾气。这活儿干下来，人是麻的。

后来我才知道这有个专门的说法。N 个助理、M 个数据源，就得写 N×M 段适配——这不叫生态，这叫乘法。

### MCP 的思路简单到有点粗暴

MCP（Model Context Protocol）的做法是：**把"怎么接外部系统"这件事，从每个助理里抽出来，做成独立的标准。**

<Label>像 USB-C，也像 JDBC</Label>

连接器写一次，所有客户端都能用；助理换谁都无所谓，因为外面的世界对它来说长一个样。

有几个关键词值得记一下：

- **Client**：在 Agent 那侧，负责发现和调用
- **Server**：提供能力的一端，可以是个本地进程，也可以是个远程服务
- **传输**：本机进程之间用 stdio，跨网络用 HTTP
- **三种原语**：`Tools` 是能干活的手，`Resources` 是能读的书架，`Prompts` 是使用说明书

<Collapse title="一个更笨但好记的说法">
Agent 像一个人，MCP 像 USB-C。

以前你接外设，得看这个人支持哪种接口，插不上就去找转接头。现在接口统一了，外设做一次，插谁都能用。
</Collapse>

这一层补上的，正好是"系统调用接口"。

到 2026 年，MCP 已经从 Anthropic 一家推的协议，变成了各家公司都在接的基础设施。我自己的体感更直接：现在换个新助理，接外部系统要重新学一套配置的情况，已经少很多了。

### 但它不是银弹

MCP 把接口统一了，安全问题一个没少，反而多了一个口子。

<Label>接上就等于授权</Label>

一个 Server 声明了能读你的仓库，那它就真的能读。**协议只管"怎么连"，不管"该不该给"。**

再叠上我自己的教训——被攻击那一回，我是过了一周翻日志才发现异常的。那次之后我算明白一件事：在 Agent 时代，审计日志不是加分项，是保命的。**一个你查不清它干了什么的助手，等于一个你不认识的人在你家干活。**

而且 MCP Server 本身成了新的供应链入口。装一个 Server，跟当年往电脑上装个来路不明的软件，是同一件事。

<Aside>
**我的判断**：MCP 让 Agent 有了统一的"系统调用"，可操作系统之所以是操作系统，靠的是权限模型、隔离和恢复这三样。这三样，MCP 一个都没解决。

所以现在的 Agent 更像什么？像一个**拿着 root 权限的 shell**：手很灵活，什么都能干，但你得自己盯着。
</Aside>

## 第三部分：离操作系统还差的三样

### 差一套进程管理

操作系统会分配资源：谁多给点 CPU，谁内存紧张就降级，谁卡死了先隔离谁。

Agent 现在基本没这一层。

<Card title="我遇到的情况">
我让 Agent 同时干两件事，一件改代码，一件发通知。

改代码那件中途要读文件，发通知那件顺手把文件结构改了。等我回头看，代码还在，但已经不是我要的样子了。

没有隔离，这两个任务共享同一个世界，谁也不知道对方动了什么。
</Card>

我现在的做法很土：能串行就串行，除非我确实想看它们打架。

### 差一个权限模型

这是最要命的一环。

一个成熟的 Agent 平台，至少得有：能力分级、读写分离、按目录或按域授权、每个动作留痕、能回放、能撤销。

现在的现实是，权限常常就两个选项：全给，或者全不给。全给很危险，全不给它什么都干不成。

<Label>最小权限</Label>

而这恰好是操作系统四十年里最核心的那条经验——**默认拒绝，按需授予**。这条经验，Agent 这边还在补课。

我自己的感受就是：现在我愿意让 Agent 碰的东西，还是得先想一遍"它最坏能干什么"。

### 差一套记忆的文件系统语义

操作系统里的文件有版本、有锁、有权限位、有删除确认。

Agent 的"记忆"现在更像往文件里追加字符串。没有版本，没有冲突处理，没有过期策略。记的东西越多，噪声越大，模型在里面翻找的成本也越高。

<Collapse title="我的观察">
我那台 Agent 的记忆目录，用了不到一个月就有点臃肿。

有些条目是它自己写的观察，有些是从对话里摘的结论，还有一些我完全看不出是怎么来的。

它们全都同等地位地被"记住"。没有哪条更可信，也没有哪条会自己过期。
</Collapse>

如果记忆能像 git 一样有版本、能标来源、能按时间衰减，Agent 的长期价值会高一个量级。

## 总结

拆完这一遍，我自己的结论挺朴素的。

**Agent 已经在做操作系统的事了**，而且比我想的快：

- 常驻运行时 ✅
- 持久化状态（记忆）✅
- 统一调用协议（MCP）✅
- 工具生态 ✅

**还差三样**，每一件都很难：

- 进程隔离与调度 ❌
- 权限模型与审计 ❌
- 记忆的版本与生命周期 ❌

<Aside>
**一句话**：现在的 Agent，像一台功能很全、但还没装安全策略的机器——手上的能力已经齐了，规矩还在路上。
</Aside>

### 几条我自己在用的判断标准

下次再看到一个号称"AI 操作系统"的东西，我现在的看法是这样的：

1. **它的工具走不走统一协议。** 走 MCP 或类似标准，说明有人在认真做；不走，多半是把能力焊死在自己产品里。
2. **它有没有审计日志。** 能不能查清楚它到底动了什么。查不清的，别放重要数据。
3. **它崩了能不能恢复。** 配置和记忆是文件还是内存，一测就知道。
4. **它怎么管你的 Token。** 把上下文当内存配额来算预算的，通常更靠谱。
5. **权限是不是最小化的。** 默认全开的，省事，但也危险。

前四条我都有切身体会，第五条我还在补。

<Card title="最后想说的话">
折腾了这些天，我现在的想法是：

**别急着把 Agent 当成"更聪明的聊天框"，也别急着把它当成"能替你干活的员工"。**

它更像一台**刚从实验室搬出来的机器**。能力已经超出了操作系统诞生那会儿的想象，可配套的规矩还在摸索。

我们要做的不是怕它，也不是全靠它，而是搞清楚它现在能干什么、不能干什么、怎么在它的能力范围内安全地干活。

这跟我当年学着用搜索引擎的感觉差不多——工具越强，越得知道边界在哪。
</Card>
